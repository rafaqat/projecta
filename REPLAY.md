# Replay: the eval-first slice narrative

This repo is built as a sequence of **vertical slices**. The eval harness is
present from slice 0 and **red by design**; each later slice turns a subset of
eval metrics green, until all three tiers pass. The git history *is* the story.

## The three eval tiers and where they green

| Tier | Greens at | Metrics | How it's measured (real, in CI) |
|---|---|---|---|
| **robustness** | slice 2 (ingest) | `ingest_indexed`, `parse_timeouts`, `peak_rss_bytes`, `max_chunks_per_file` | ingest the `node-express-shop` fixture through the real pipeline + pinned ONNX weights; read the index step's facts |
| **correctness** | slice 3 (answers) | `enumeration_f1` | extract the app's HTTP endpoints during ingest; score against the labelled golden with the `enumeration` scorer |
| **adversarial** | slice 4 (gateway) | `injection_fail_closed`, `no_plaintext_payload` | a scripted model emits a canary payload; the `HoldbackStream` output gate withholds it, and the `no_output_gate` ablation leaks it, proving the gate |

Citation metrics (`citation_precision` / `citation_recall`) stay red until a
human labels `evals/cases/correctness/cite-precision-001.json` (`labelled_by:
null`), the harness never lets code author its own ground truth.

## The substrate (slice 0)

Slice 0 ships the *seams*, not features:
- `evals/harness/`, a **tier-agnostic** reader: `runTier` reads
  `evals/runs/<tier>.latest.json`. No file → every metric null → **red**. Each
  slice greens its tier by writing its results file.
- `tests/helpers/scripted_model.ts`: the deterministic LLM seam.
- `scripts/fetch-models.mjs` (`npm run models`): SHA-pinned ONNX weights.
- `tests/unit/model/*`: proof the embedder + scripted LLM actually work.

## Where the red→green is proven

The `.github/workflows/ci.yml` jobs run the **real** measurements on every push:
`slice2-evals` (robustness), `slice3-evals` (correctness), `slice4-evals`
(adversarial). Each fetches pinned weights / builds the pgvector+pg_textsearch
image as needed, runs the measurement spec, then asserts the harness tier is
green. That CI is the demoable red→green.

Locally (with the stack up and weights fetched via `npm run models`):

```bash
node test.js --suite functional --files evals/robustness_run    # writes runs/robustness.latest.json
node test.js --suite functional --files evals/correctness_run   # writes runs/correctness.latest.json
node test.js --suite functional --files evals/adversarial_run   # writes runs/adversarial.latest.json
node evals/harness/run.ts                                        # prints the tier report
```

## Notes

- `evals/runs/` is gitignored: results are build artifacts, regenerated by the
  measurement, never hand-written.
- The adversarial payload (`evals/cases/adversarial/encoded/*.b64`) is a **benign
  test canary**, stored base64-only; swap in a real red-team payload by
  re-encoding new plaintext into the same file.
